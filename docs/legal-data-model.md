# Схема юридических данных

Каждая мера хранится отдельно от интерфейса сайта.

Обязательные поля:
- id и название;
- федеральный или региональный уровень;
- территория действия;
- статус;
- дата начала и окончания действия правила;
- машиночитаемые критерии;
- НПА;
- официальный источник;
- дата ручной проверки;
- статус проверки.

## Правило публикации
`verified` означает, что карточка может участвовать в выдаче. `needs_review` означает, что мониторинг обнаружил изменение либо данные ещё не сверены. Такие изменения не должны автоматически менять юридический вывод пользователю.

## Обновления
Мониторинг официальных источников служит сигналом. После сигнала новая редакция НПА сверяется по содержанию, дате публикации и дате вступления в силу. Это позволяет заранее хранить будущие изменения и включать их в нужную дату.


## Автоматическое включение по датам

Пользовательская выдача дополнительно проверяет `effective_from` и `effective_to`.

- Будущая проверенная мера может храниться в базе заранее, но до `effective_from` не показывается.
- После наступления `effective_from` она начинает участвовать в подборе автоматически.
- После `effective_to` мера автоматически исчезает из актуальной выдачи.
- Это не отменяет ручную юридическую проверку: автоматизация управляет только датой публикации уже проверенной записи.


## Поля для полезной карточки

Помимо юридического основания карточка может содержать:
- `frequency` — единовременно / ежемесячно / ежегодно;
- `application` — официальный способ или место обращения;
- `amount` — сумма, диапазон, формула, натуральная льгота или варианты;
- `official_urls` — официальный источник для самостоятельной проверки.

Эти поля не заменяют критерии права и публикуются только при наличии подтверждения в официальном источнике.


## Белый список источников

Для статуса `verified` официальный URL должен вести на разрешённый государственный домен. Сейчас автоматическая проверка допускает федеральные источники СФР и официальные правовые порталы, а также подключённые официальные домены Самарской области и Красноярского края. При подключении нового региона его официальный домен добавляется в whitelist после проверки.

Сторонние справочники, СМИ, банки, блоги и агрегаторы не могут быть основанием для статуса `verified`.
